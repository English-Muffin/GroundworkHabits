# Groundwork Habits

Habit tracker, weekly task tracker, goal planner and insights in one offline-first app.
Ships as a single static page (`www/index.html`) wrapped for the web (PWA), Windows and macOS (Tauri) and Android (Capacitor).

The look is modelled on a reference demo video: near-black UI, teal accent, circular check grid.
It has its own name and branding (Groundwork Habits: layered "foundation" mark). Do not copy the original product's name, logo or copy. Every name uses Groundwork (keys `groundwork-*`, `groundwork.json`, `groundworkFS`, `GroundworkNative`, appId `com.groundwork.habits`, desktop config and backups `%APPDATA%/Groundwork Habits`). The app was called Daybook until 1.7.2; the only places that still say so read old data once: `index.html` copies `daybook-*` localStorage keys, `main.js` copies the old profile folder (marker `renamed.txt`, a stray new folder is set aside) and reads an old `daybook.json` in the data folder, `Folder.java` reads it on Android, and the uninstaller's erase removes both profile folders. The new appId means Android installs it as a new app (users export and import).

## Layout
- `www/index.html` (HTML shell), `www/app.css`, `www/js/*.js` (the app, no build step, no dependencies: classic scripts loaded in order by index.html that share one scope, like one file split by area: core, habits, tasks, goals, settings, render, events, extras, boot), `www/fonts/` (Space Grotesk woff2, SIL OFL)
- `www/sw.js`  offline cache. Bump `VERSION` whenever shipped files change
- `www/manifest.webmanifest`, `www/icons/`  PWA metadata and icons
- `tauri/`  desktop shell for Windows and macOS (see "Windows and macOS on Tauri"). Its bridge gives the page `window.groundworkFS` so the user can pick a data folder (Settings > Data folder); data is mirrored to `<folder>/groundwork.json` (sync, tmp+rename), re-read on focus. Picking a folder that already has a save asks: replace (old file kept as `groundwork-replaced-*.json`) or load (second warning). Picking a Google Drive/OneDrive/Dropbox synced folder is the cloud sync story. The Electron shell was removed after 1.7.5; the Tauri app still moves data over from an old Electron install on first start
- `capacitor.config.json`  Android wrapper (the `android/` folder is generated, never commit it)
- `assets/`  source icon (1024 png, ico) and splash
- `.github/workflows/build.yml`  builds the Windows setup and portable exe, the macOS universal zip and the APKs (full and Lite) in CI
- `tests/smoke.py`  Playwright smoke tests (157 checks, desktop and phone; the desktop shell is checked by `tests/tauri_app.py`)
- `tests/visual.py`  screenshot comparison, light and dark (local only; fixed clock + demo data). `UPDATE=1` accepts a new look after checking the PNGs in `tests/visual/`
- `tests/launch_check.js`  CI: starts the packaged desktop app and waits for it to render
- `tests/device_android.py`  real-device check on the BlueStacks instance named "Groundwork Habits testing" (finds it in BlueStacks' config, starts it, connects only to its adb port): reminder in the background, Yes from the notification without opening the app, calendar, widget, Save to. Run before every release
- `tools/i18n/`  translations: `<lang>.txt` (numbered lines matching `source.json`), `build.py` checks them and writes `www/i18n/<lang>.js`
- `native/release.gradle`  applied to the generated `android/app/build.gradle`: version from package.json, release signing from `GROUNDWORK_KEYSTORE*` env (CI secrets `ANDROID_KEYSTORE_BASE64/PASSWORD`, `ANDROID_KEY_ALIAS`; the key lives outside the repo)
- `tests/stress.py`  stress test (heavy data, 320-1920px, all themes, random clicks, edge dates); writes report.txt

## How the app scripts (`www/js/`) work
Top-level names in any file are visible to the others, but load-time code only sees files loaded before it: code that runs at load (not inside a function) must only call things defined in its own or an earlier file. A new file goes into index.html's list and `sw.js` CORE (smoke checks the list matches). `npm run lint` (ESLint, names read with espree) catches undefined names across files; `npm run test:unit` (tests/unit.js) runs the pure logic in Node with a stub DOM.
- State is one object `S`: `{v, habits, log, tasks, goals, journal, quits, count, notes, amt}` (`v` = data version, migrations go after `let S=load()`), saved to `localStorage` key `groundwork-v2` by `save()`.
  - `habits`: `{id, name, type: 'daily'|'weekly'|'monthly', color}`
  - `log[habitId]`: set of keys. Daily `YYYY-MM-DD`, weekly `YYYY-MM-Wn` (W1 = days 1-7 of the month), monthly `YYYY-MM`
  - `tasks['YYYY-MM-DD']`: `{items: [{id, text, done, cal?}], mind: {energy, focus, motivation} | null}`
  - `habits[].target` (1-99): taps needed per period. `count[habitId][key]` holds partial taps; `log` still marks done, so stats are unchanged. Use `tap(h,k)` to toggle
  - `habits[].per` (1-7): days per week for daily habits (Today shows `n/per this week`). A habit's type can change; ticks of the old type stay in `log` under their own key format
  - `habits[].track`: `check` | `count` (uses `target`) | `amount` (`unit`, optional `goal`; numbers in `amt[habitId][key]`, `log` marks done once the goal is met; `setAmt()`)
  - task items may carry `goal` (id of a goal measured by tasks), `rem` `{t,m}` (a one-off reminder on that day: bell button `.tkb`, modal `trem`; same engine as habits, ids 2000+ on Android, `findT()`), `rep` (series id of a repeating task, see `repeatDates()`), `cal`/`hidden`/`pin` (calendar events; `pin` = user moved it to another day)
  - `habits[].off`: pauses `[{f,t?}]` (day keys, no `t` = still paused). `pausedK`/`pausedNow`; `isRest` counts paused days, so streaks, freezes, %, reminders and the widget skip them. Paused habits are hidden from Today; the habit dialog has Pause / Resume (resume on the start day removes the pause)
  - `habits[].tod`: `m`|`a`|`e` (daily only). Today groups daily habits by time of day once any has one (`todRows`, `TODS`): the current part first, then later parts, Anytime, earlier parts
  - `habits[].rem`: `{t:'HH:MM', m:'ask'|'alarm'}` or null, a per-habit reminder (see Habit reminders)
  - `notes[habitId][key]`: short note for that day/week/month
  - `quits`: `{id, name, since: 'YYYY-MM-DDTHH:MM' local, best: days}` quit streaks shown on the Streaks tab (route `#achievements`)
  - `goals`: `{id, title, area, pct, due?, pin?, kind?, steps?, unit?, target?, start?, log?: [{d,v}], habit?, since?}`. `kind` (`gKind`): pct (slider), steps, num (log amounts add up to target, e.g. €; `recur` {v,every:'w'|'m',from,last} adds entries marked `a:1` via `applyRecurring()`), range (start → target, latest logged value), habit (ticks of a habit since a date), tasks (tasks with `goal` = this id, `gTasks`). `arch` hides a goal under Archived. Deadlines (`due`) notify 7 days before and on the day at 09:00 (`goalDue`). `gPct()` is the source of truth (stored `pct` is a copy for exports); `gLine()` the one-line status; `IDEAS` holds starter goals per area.
  - `areas`: custom life areas `[{name,color}]` next to the built-in `AREAS` (`allAreas()`, `areaCol()`); renaming moves goals, deleting needs the area to be empty. Goals screen: life areas filter (`goalArea`), pinned first, edit in the `goal` modal. `journal['YYYY-MM']`: monthly reflection text
- `render()` rebuilds `#main` from string templates (`vToday`, `vHabits`, `vTasks`, `vGoals`, `vInsights`, `vAch`) and `#modal`.
  It preserves scroll positions, so keep that behaviour if you change it.
- One delegated `click` listener handles every `data-act="..."` button. Add new actions to its `switch`.
  Actions that only change UI state set `persist=false` so nothing is saved.
- Range sliders, textareas and the task input write to `S` directly on `input` and must not trigger a full re-render
  (it would steal focus). Use `focusSel` to re-focus after a deliberate re-render.
- `TODAY` is a `let` and is refreshed on focus, visibility change and every minute (`refreshToday`).
- Dates are local time. Task weeks start on Sunday. Always escape user text with `esc()`.
- Hash routes: `#today #habits #tasks #goals #insights #achievements`.

## PIN encryption
Exports and weekly backups are encrypted too when a PIN is set; importing an `enc1:` file asks for that PIN (`impin` modal). Android fingerprint unlock (`Bio.java`) keeps the PIN encrypted by a biometric-bound Keystore key; `bioTry()` runs on the lock screen.
With a PIN, `S` is saved as `enc1:<salt>:<base64>` (AES-GCM, key from PBKDF2 of the PIN, in memory only). Until the PIN is entered `encWait` is true and nothing may save, sync reminders or pull the calendar. Old hash-only PINs upgrade on unlock. Desktop waits for pending encrypted saves before closing (`app:flush`). Each window unlocks itself.

## Large text, high contrast, speed
Android's font size zooms px text too, so long words wrap (`body{overflow-wrap:anywhere}`) and grid/flex children that hold text need `min-width:0` / `minmax(0,1fr)`. Windows high contrast (`forced-colors`): data drawn as coloured blocks (bars, heatmap, dots) sets `forced-color-adjust:none`; the current tab and selected segment use `Highlight`. Speed: `daysFrom()` shares one list of day keys for every habit's freeze replay; `save()` makes one JSON pass (`at` re-added as the last key). Smoke checks names, Tab reach, reduce motion and high contrast.

## Streak freezes
Per habit `h.fz` {off, every 3-30, max 1-5} (default every 7, max 3). `freezeOf(h)` replays an every-day habit's history: 7 done in a row earn a freeze (max 3), a missed day uses one. `curStreak` and `dailyStats` honour them; nothing extra is stored. Switch: `feat('freeze')`.

## Translations
English is written in the code and is the key. `index.html` picks the language (`P.lang`, else the device language) and loads `i18n/<lang>.js` before the app scripts; `trDom()` swaps text, placeholders and labels after each render (on the template before `morph`, and on menu/modal/nav/lock), `tx()` translates toasts and notification text. Day and month names come from `Intl`. User content (`NOTR` selector: names, notes, task text) is never translated. New UI text: add it to `tools/i18n/source.json` (or a pattern for text with numbers/names) and every `<lang>.txt`, then run `python tools/i18n/build.py`. Languages: en pt es fr de it nl pl ru zh ja ar he. Arabic and Hebrew set `dir=rtl` in index.html: CSS uses logical properties (`margin-inline-start`, `inset-inline-end`, `text-align:start`), never physical left/right except centring (`left:50%`); `ic()` marks prev/next/back arrows `.flip` so they mirror; arrow-key reordering and auto-scroll to today check `document.dir`. Arabic dates use Latin digits (`ar-u-nu-latn`).

## Accessibility
Text greys (`--g4a`..`--g8a`) meet WCAG AA 4.5:1 on cards in dark and light; light theme darkens `--red --green --flame --amber --purple --star` for text. Icon-only toggles are `role=checkbox` + `aria-checked`, never `aria-pressed` + `aria-label`: Android's WebView drops the label of a toggle button, so TalkBack would read it unnamed (`aria-pressed` stays only on buttons with visible text). Check with `uiautomator dump` (NAF=true = no name). Web data folder (Chrome/Edge): `WEBF` gives the Android folder calls (`FOLD`) through `showDirectoryPicker`; handle in IndexedDB (`idbKv`), "Reconnect" when the browser wants permission again. Dialogs (`#modal [role=dialog]`) take focus on open, trap Tab, and return focus to the opener (`dlgFocus`, found again by `data-act` if re-rendered).

## Settings page
`#settings` (and `#settings/<section>`, sections in `SETSECS`) is a page, not a dropdown: `vSettings()` builds it from `setSection(k)` with row helpers `srow`/`sgo`/`sgrp`/`sw` (switches are `role=switch`). Desktop (`wideSet()`): side list + every section on one page, the list follows the scroll (`spySettings`). Phones: the section list with a status line each (`setStatus`), then one section with a back button. Search (`#setQ`, `filterSettings`) hides non-matching rows without re-rendering. The gear opens it, Esc / back returns to `setBack`. Destructive actions sit in the red "Danger zone" group and ask twice. Feature descriptions live in `FEATD`. `P.lockIdle` (minutes) sets the auto-lock.

## Rendering
`render()` builds HTML strings, translates them on a detached template and `morph()`s `#main` in place (only changed nodes update, focus and scroll survive). Elements that bind listeners use `onlyOn()` so re-renders replace them.

## Colour picker
`colorPicker(f,hex,presets,label)` is the only colour control (accent, habit, life area): preset swatches plus a custom swatch (`cpopen`, state in `cpOpen`) that opens hue / saturation / lightness sliders and a hex field inside the card, no system dialog. `setColor(f,hex)` keeps every field in sync without re-rendering; add a target to `COLOR_SET`. Tab names under the nav icons can be hidden (`P.tabNames===false` sets `html.notabnames`); on phones the bar is 7 equal columns.

## Android back button
`GroundworkNativePlugin.load()` registers an `OnBackPressedCallback` and sends a `back` event; `onBack()` (js/events.js) closes a dialog or open menu, leaves Settings (like `setback`), steps back through the screens visited (`navHist`, filled on `hashchange`) and then to Today; on Today the first back shows a toast and a second one within 2 s calls `NB.exitApp()`.

## Test-only features
`const TESTING=true` in js/core.js shows "Load demo data" and exposes `window.GroundworkTest` (all tests rely on them). Release builds turn them off: the CI step "Turn off testing features" runs `tools/release_strip.js` on `v*` tags only (it fails if the line is missing). Local `dist/` test builds keep them. Never commit `TESTING=false`.

## Windows and macOS on Tauri (both editions)
Windows ships on Tauri: `tauri/` (Rust, Tauri 2) embeds `www/` in one exe using Windows' own WebView2 (full ~5 MB, Lite ~4 MB; installers ~3 and ~2 MB). macOS is on Tauri too (`npm run dist:mac` = `tools/build_tauri_mac.js` on a Mac: cargo for aarch64 and x86_64, `lipo`, a hand-made .app with Info.plist and icns, ad-hoc `codesign`, `ditto` zip; ~10 MB instead of 166). WebKit has no debugging port, so CI checks macOS with `GROUNDWORK_SELFTEST=<file>`: the main window writes a JSON report (title, edition, bridge) and the app quits (`tests/launch_check.js` on darwin). On macOS the bridge reaches the data folder at `gw://localhost`, on Windows at `http://gw.localhost`. Tests open WebView2's debugging port with `GROUNDWORK_DEBUG_PORT` (CI runners ignore `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`). `npm run dist:win` = `tools/build_tauri_win.js`: `cargo build --release` (`--features full` for the full app, none for Lite, so Lite has no network code), renames `groundwork-habits.exe` to "<productName>.exe", copies it as the portable download (no launcher) and wraps it with our installer (`APP_DIR`).
- Bridge `tauri/src/bridge.js` gives every window `window.groundworkFS`. Async calls are Tauri commands (backup, open backups, widget, ask pop-ups, show main, flush; full: choose, fetch_cal, update_check, update_install). The page reads and writes the data folder synchronously, so the full build answers synchronous XHR on `http://gw.localhost` (`/folder /read /write /reset /electron /electron-done`, Origin checked); Lite has no `gw` and its bridge answers "none".
- `tauri/src/full.rs` has the desktop rules first written for the Electron app (same wording): config.json and backups in `%APPDATA%\Groundwork Habits` (so a chosen folder carries over), replace/load prompts (rfd; test hooks `GROUNDWORK_TEST_PICK`/`GROUNDWORK_TEST_ANSWERS`), `daybook.json` fallback, calendar (https every hop, 5 MB/20 s, public addresses only: `tauri/src/net.rs` checks inside the DNS resolver, with `cargo test --features full`), updates (GitHub hosts only, sha256, setup /update after exit; only when "Uninstall Groundwork Habits.exe" sits next to the exe).
- Moving from Electron: on the first start the bridge asks `/electron`, which reads the Electron profile's localStorage (Chromium leveldb, from a temp copy: `_file:// <key>`, value byte 0 = UTF-16LE, 1 = Latin-1) for `groundwork-*`/`daybook-*` keys, puts them into WebView2's storage before the app loads, then writes `moved-from-electron.txt`. The Electron profile is kept.
- Gotchas: the main window is created in `setup()` with the bridge as `initialization_script`; window commands must be `async` (sync ones deadlock on Windows); a `#` in a window URL is encoded, so the widget/pop-up route is set from the start-up script; the service worker is skipped (`__TAURI_INTERNALS__`); `taskkill` reaches only one of the app's windows, tests close the main window with WM_CLOSE.
- Data: WebView2 storage in `%LOCALAPPDATA%\<app ID>`; the uninstaller's erase removes it, `%APPDATA%\<app ID>` (Lite backups) and `%APPDATA%\<Name>`.
- `python tests/tauri_app.py "<absolute path to exe>"` drives the real exe over WebView2's debug port (24 checks full, 13 Lite). It sets the app's data folders aside and restores them; it refuses to run if a `.test-bak` from an interrupted run is still there (that may be real data). Needs Rust and VS Build Tools (C++) locally; CI runners have both.

## Code signing (Windows, SignPath)
Release tags only, and only once the `SIGNPATH_API_TOKEN` / `SIGNPATH_ORGANIZATION_ID` secrets exist. Two passes in build.yml so every exe a user runs is signed: 1) the app exe plus the uninstaller (`UNINST_ONLY=<file> node tools/build_setup.js` writes just the uninstaller), 2) the setup rebuilt around the signed parts (`UNINST=<signed uninstaller>`), then signed itself; the signed app exe is also the portable download. ## Drag to rearrange
Insights is one 12-column grid (`#main.idash`, boxes `.q` quarter / `.h` half), so every box is its own card. Any `[data-drop=LIST]` container whose children are `[data-drag=LIST][data-id]` with a `.grip` button can be reordered by pointer (mouse and touch, `touch-action:none` on the grip) or arrow keys on the grip. `commitDrag()` writes the order: tasks (between days via `.tlist[data-k]`), `habits-<type>`, goals, quits, and `cards` (top-level blocks of Today/Insights, order in `P.layout[view]`). Calendar tasks have no grip. Switch: `feat('drag')`.

## Design tokens (CSS variables in `:root`)
Spacing scale `--sp-1..5` = 4, 8, 12, 16, 24px: 12px between a header and its content, 8px between items, 16-24px around cards. The stress test flags anything closer than 10px to a progress ring.
`--bg #080808`, `--card #0f0f0f`, `--teal` (= `--accent`, default Moss `#9cc96b` to match the logo; `--on` is derived from the accent), `--red`, `--purple`, `--flame`, `--star`. Font: Space Grotesk (bundled, system fallback).
Dark is the designed theme. Settings > Customize adds accent colours (sets `--teal`) an AMOLED theme (`html.amoled`, darkest greys set to #000) and a light theme (`html.light` overrides the `--gXX` grey tokens, one per original dark grey, and darkens the accent), stored in localStorage `groundwork-prefs`, separate from data. Use `var(--teal)` (style, not SVG attributes) for accent colour and `var(--gXX)` tokens, never raw greys, so both themes work. Breakpoints: 900px (stack columns) and 760px (bottom nav, narrower sticky name column). From 1500px wide `.app` has no max width (3vw side padding), so columns and cards get larger on big screens; text stays the same size (Windows display scaling handles 4K).

## Conventions
- Plain modern JS, no frameworks, no build step. Keep it one self-contained file unless there is a strong reason to split.
- UI copy: sentence case, typographic apostrophes (’), no emoji.
- Icon-only buttons need `aria-label`. Keep visible `:focus-visible` outlines.
- Nothing may depend on hover: it must also work by touch.
- Do not add runtime dependencies for the web app. Playwright and the Tauri/Rust toolchain are dev tools; the only `dependencies` entries are the Capacitor notifications plugin and the local `groundwork-native` plugin, both for the Android build.

## Gotchas already hit
- Replacing `innerHTML` resets scroll. `render()` saves and restores it.
- The Insights dropdown went under the chart on phones until `.sel` got `position:relative; z-index:20`.
- Hover-only controls (delete buttons) are unusable on touch. Editing and deleting habits now live in the modal (tap the habit name).
- The service worker is skipped inside Tauri and Capacitor (see the registration guard at the end of the script).
- Android WebView cannot download blob links. On Android every export goes through `GroundworkNative.saveFile` (system "Save to" picker); elsewhere Web Share on mobile, else a download.
- Fonts are bundled (`www/fonts`), no network needed.
